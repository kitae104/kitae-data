데이터 분석이란 무엇일까요?

데이터 분석은 한 마디로 "쌓여있는 숫자에서 의미 있는 패턴이나 답을 찾아내는 과정"입니다. 숫자 표가 잔뜩 있어도 그냥 보면 어지러울 뿐이죠. 그 표 안에 숨어 있는 "어, 이게 좀 이상한데?"나 "오, 여기에 규칙이 있네!"를 찾아내는 것이 분석가의 일입니다.

분석의 출발점은 항상 "질문"입니다. "이번 달 불량률이 왜 높아졌지?", "어떤 조건일 때 합격률이 떨어지지?", "센서값이 평소와 다르게 움직이는 시점이 있나?" 같은 질문을 데이터에 던지고, 표·그래프·통계를 도구 삼아 그 답을 찾는 것이죠. 이번 강의도 그런 질문 한 개를 끝까지 따라가 보는 시간입니다.

🧩

분석은 퍼즐 맞추기와 비슷합니다. 흩어진 조각(숫자)을 하나하나 살펴보고, 비슷한 것끼리 묶고, 그림(패턴)을 찾는 과정이에요. 처음에는 막막해도 한 조각씩 맞춰 가면 그림이 보입니다.

라이브러리(library)가 뭐예요?

파이썬에는 누군가 미리 만들어 둔 도구 모음들이 있습니다. 이런 도구 모음을 라이브러리라고 불러요. 우리가 직접 표 다루는 코드, 그래프 그리는 코드를 다 짤 필요 없이 — 이미 잘 만들어진 도구를 가져다 쓰면 됩니다.

파이썬이 강력한 이유 중 하나가 바로 이 풍부한 라이브러리 생태계예요. 수많은 개발자가 무료로 공개한 라이브러리를 "import 한 줄"로 불러와 사용할 수 있습니다. 오늘 우리가 쓸 pandas, numpy, matplotlib, seaborn도 모두 그런 라이브러리입니다.

💡

import는 "앱을 실행"하는 것과 같아요. import pandas는 판다스 앱을 켜는 것이고, as pd는 그 앱에 "pd"라는 짧은 별명을 붙이는 것입니다. 매번 "pandas"라고 길게 쓰기 귀찮으니까요! 그리고 pd라는 별명은 전 세계 데이터 분석가들이 거의 모두 쓰는 관습적인 약속이에요.

CSV 파일 읽어서 DataFrame 만들기

CSV는 "Comma Separated Values" — 쉼표로 구분된 값들이 든 텍스트 파일입니다. 엑셀로도 열 수 있는 가장 일반적인 데이터 파일 형식이에요. 윈도우 메모장으로 열어보면 2024-03-01,302.5,1011.6,... 처럼 값들이 쉼표로만 구분되어 줄줄이 적혀 있는 걸 볼 수 있습니다. pd.read_csv() 한 줄이면 이 텍스트가 우리가 다루기 좋은 표로 바뀝니다.

📦

DataFrame = 엑셀 시트 한 장이라고 생각하세요. 행은 측정 기록 한 줄, 열은 측정 항목 한 가지입니다. pd.read_csv('파일.csv')는 "이 파일을 표로 읽어줘!"라는 명령이고, 결과를 df 같은 변수에 담아두면 그 뒤로는 df를 통해 모든 분석을 진행하게 됩니다.

해당 열에 결측값(빈 칸)이 있다는 신호입니다! 예를 들어 온도_섭씨가 195라면 5개가 비어 있다는 뜻이에요. 결측값은 평균·표준편차 계산에서 자동으로 빠지기 때문에, count 숫자만 봐도 결측이 어디에 얼마나 있는지 알 수 있습니다. 3단계에서 본격적으로 처리할 거예요.

📌

info()의 출력을 읽는 법
• Non-Null Count = 비어 있지 않은 값의 개수 → 200보다 작으면 결측값 있음
• Dtype = 데이터 타입 → float64(소수), int64(정수), object 또는 str(문자열, pandas 3.0부터 str로 표시)
데이터 타입이 예상과 다르면(숫자여야 하는데 object로 잡혀 있다든지) 그 자체로 데이터 품질 문제의 신호입니다.

원하는 "열(컬럼)"만 골라 보기

12개 열을 한꺼번에 보면 어지러우니, 보고 싶은 열만 골라 뽑는 방법을 익혀봅시다. 이때 핵심은 대괄호 [ ] 안에 열 이름을 따옴표로 묶어 적는다는 것입니다. 그리고 한 개 열을 뽑는 것과 여러 개를 뽑는 것이 모양이 살짝 달라요. 이 두 가지의 차이를 분명히 알면 pandas의 절반은 이해한 셈입니다.

04_select_columns.py 
## 한 개 열만 선택 → 결과는 Series (열 하나짜리)
df['온도_섭씨']            # 온도_섭씨 한 줄만 200개

## 여러 열 선택 → 결과는 DataFrame (대괄호 두 겹!)
df[['온도_섭씨', '압력_Pa', '합격여부']]

## 한 개 열의 통계 계산
print(f"평균 온도: {df['온도_섭씨'].mean():.2f}°C")

❗

대괄호 한 겹 vs 두 겹의 차이
• df['온도_섭씨'] → 1차원 Series (한 줄)
• df[['온도_섭씨']] → 2차원 DataFrame (한 열 짜리 표)
여러 개 열을 한꺼번에 뽑을 때는 반드시 대괄호 두 겹을 써야 합니다! 안쪽 대괄호는 "이 컬럼 이름들의 리스트"이고, 바깥 대괄호는 "이 리스트로 데이터프레임 만들어"라는 뜻입니다.

원하는 "행"만 골라 보기 — loc vs iloc

이번에는 가로줄(행)을 골라내는 방법입니다. pandas에는 두 가지 방식이 있어요. loc은 이름(인덱스 라벨)으로, iloc은 위치(번호)로 찾습니다. 처음에는 헷갈리지만 한 번만 정리해두면 평생 써먹는 도구입니다.

🔍

loc = "이름으로 찾기" — 「김민준 학생 어디 있어?」
iloc = "번호로 찾기" — 「3번 자리 학생!」 (i는 integer = 정수의 약자)

05_loc_iloc.py 
## iloc - 위치(번호)로 선택. 0부터 시작!
df.iloc[0]          # 첫 번째 행 (가장 위 한 줄)
df.iloc[1:5]       # 1~4번 행 (5번 미포함!)

## loc - 인덱스 이름(라벨)으로 선택
df.loc[0]              # 인덱스가 0인 행
df.loc[0:4, ['온도_섭씨', '합격여부']]  # 행+열 동시 지정
⚠️

iloc과 loc의 슬라이싱 차이 — 이걸 자주 헷갈립니다!
• df.iloc[1:5] → 1, 2, 3, 4번 (5번 미포함, 파이썬 일반 규칙)
• df.loc[1:5] → 1, 2, 3, 4, 5번 (5번 포함! loc은 양쪽 다 포함)
"loc은 라벨이라 끝까지 포함, iloc은 정수라 끝 미포함"이라고 외워두세요. 실무에서는 iloc보다 loc이 더 자주 쓰입니다(인덱스가 단순한 번호가 아닐 때가 많으니까요).

1
결측값(NaN)이 뭐예요?

데이터의 어떤 칸이 비어 있는 상태를 결측값이라고 부릅니다. pandas는 이걸 NaN (Not a Number)으로 표시해요. 반도체 공정에서는 센서가 잠깐 꺼지거나, 측정값을 기록 못 하면 그 칸이 비게 됩니다. 사람이 설문지를 일부만 채우거나, 시스템이 잠깐 오류 났을 때도 마찬가지죠.

결측값이 위험한 이유는 그대로 두면 모든 계산이 망가지기 때문입니다. 평균에 NaN이 끼면 결과가 NaN, 그래프를 그리면 빈 자리가 나오거나 에러가 납니다. 그래서 분석 본격 시작 전에 반드시 "이 결측을 어떻게 처리할지" 결정해야 해요.

🕳️

결측값이 그대로 있으면 평균·표준편차 같은 계산이 깨지거나 그래프가 이상하게 그려져요. 분석 전에 반드시 채우거나 지워야 합니다. 마치 요리하기 전에 빠진 재료를 챙기는 것과 같아요.

2
결측값 찾기

isnull()은 각 칸이 비어 있는지 True/False로 알려주고, 거기에 sum()을 붙이면 열별 결측값 개수가 나옵니다. 파이썬에서 True는 1, False는 0으로 계산되기 때문에 sum()이 곧 "True의 개수 = 결측값 개수"가 되는 원리예요.

07_check_missing.py 
# ① 열별 결측값 개수 (True를 1로 세어줌)
print(df.isnull().sum())

# ② 전체 결측값 개수 (모든 열을 합산)
print(f"전체 결측값 개수: {df.isnull().sum().sum()}개")

예측 대상(타겟) 컬럼인 합격여부에 빈 값이 있으면 골치 아픕니다. 정답이 빠진 행은 그 행 자체를 학습에 쓸 수 없으니까요. 다행히 이 데이터는 합격여부가 모두 채워져 있어요.

3
결측값 처리하는 3가지 방법

정답은 없습니다. 데이터의 양·결측 비율·맥락에 따라 적절한 방법을 골라야 해요. 가장 흔한 3가지를 정리하면 이렇습니다.

방법코드언제 쓰나요?
평균으로 채우기df['col'].fillna(df['col'].mean())값이 비교적 고르게 분포할 때
중앙값으로 채우기df['col'].fillna(df['col'].median())이상치(튀는 값)가 많을 때
행 통째로 삭제df.dropna()결측이 매우 적을 때 (전체 5% 미만 정도)

오늘은 가장 무난한 "숫자 컬럼은 평균으로 채우기"를 사용하겠습니다. 반복문(for)을 한 번 써서 숫자 컬럼 전부를 일괄 처리할 거예요.

08_fill_missing.py 
# 원본 보호를 위해 복사본을 만들어 작업
df_filled = df.copy()

# 숫자 컬럼만 골라서 평균으로 채우기
numeric_cols = ['온도_섭씨', '압력_Pa', '가스유량_slm', '전력_W',
                '진공도_mTorr', '두께_nm', '습도_pct', '진동_mm_s',
                '처리시간_sec', '냉각수온도_섭씨']

for col in numeric_cols:
    mean_val = df_filled[col].mean()
    df_filled[col] = df_filled[col].fillna(mean_val)

# 처리 후 결측 확인
print(f"처리 후 남은 결측값: {df_filled.isnull().sum().sum()}개")
⚠️

합격여부(타겟)에는 절대 fillna()하지 마세요!
예측해야 할 정답을 임의로 채우면 분석 결과 자체가 오염됩니다. 다행히 이 데이터는 합격여부에 결측이 없으니 안심하세요. 일반적으로 결측값 처리는 "입력 변수에만, 정답 변수는 손대지 않는다"가 원칙입니다.

4
중복된 행 찾고 제거하기

같은 측정 기록이 실수로 두 번 들어가는 경우가 종종 있어요. (CSV 머지, 복붙 실수, 시스템 재전송 등) 중복이 있으면 평균이 왜곡되고, 같은 데이터를 두 번 학습하게 되어 결과가 편향됩니다. duplicated()로 중복 여부를 확인하고, drop_duplicates()로 제거합니다.

09_duplicates.py 
# ① 중복된 행 개수 확인
print(f"중복 행 수: {df_filled.duplicated().sum()}개")

# ② 중복 제거
df_clean = df_filled.drop_duplicates()

# ③ 인덱스 다시 매기기 (중복 제거 후 번호가 띄엄띄엄 됨)
df_clean = df_clean.reset_index(drop=True)

print(f"정리 전: {len(df_filled)}행 → 정리 후: {len(df_clean)}행")
💡

reset_index(drop=True)는 왜 필요해요?
중복 행을 지우면 인덱스 번호가 (0, 1, 2, 4, 5, 7...) 처럼 빠진 자리가 생겨요. reset_index(drop=True)로 다시 0부터 차곡차곡 매겨주면 보기 좋고 다루기도 편합니다. 옵션 drop=True는 "이전 인덱스를 컬럼으로 남기지 말고 그냥 버려라"라는 뜻입니다.

4단계 · 탐색적 데이터 분석 (EDA)

EDA(Exploratory Data Analysis)란?
"탐색적 데이터 분석"이라고 부르고, 데이터를 이리저리 들여다보면서 패턴·이상 징후·의외의 사실을 발견하는 과정입니다. 요리에 비유하면, 본격 요리 전에 재료를 만져보고 맛보고 냄새 맡아보는 단계예요. EDA를 잘하면 그 뒤에 따라오는 모델링·예측 작업도 훨씬 수월해집니다.

1
분석에 필요한 새 컬럼 만들기

원본 데이터에 없는 정보가 필요하면 계산해서 새 컬럼을 추가할 수 있습니다. 컬럼 추가는 매우 간단해요. df['새컬럼이름'] = 계산식 한 줄이면 끝납니다.

예를 들어 1/-1로 적힌 합격여부를 사람이 읽기 좋은 '합격'/'불합격' 글자로 바꾸거나, 두께가 정상 범위 안에 있는지를 True/False로 표시해두면 뒤의 분석이 훨씬 편해집니다.

10_new_columns.py 
# df_clean을 앞으로 계속 사용 (결측·중복 처리된 깨끗한 표)

# 합격여부 1/-1 → '합격'/'불합격' 문자열로 바꿔 보기 좋게
df_clean['result'] = df_clean['합격여부'].map({1: '합격', -1: '불합격'})

# 결과 확인
df_clean[['온도_섭씨', '두께_nm', '합격여부', 'result']].head()
💡

map()이라는 함수
map({1: '합격', -1: '불합격'})는 "1을 만나면 '합격'으로, -1을 만나면 '불합격'으로 바꿔라"라는 뜻입니다. 숫자 라벨을 사람이 알아보기 쉬운 글자로 바꿀 때 유용해요. 나중에 그래프에서 범례(legend)가 자동으로 한글로 나오니 보기에도 좋습니다.

2
조건에 맞는 행만 골라내기

특정 조건(예: "불합격인 행만", "온도가 305 이상인 행만")에 맞는 데이터만 따로 보고 싶을 때 씁니다. 이걸 "불리언 인덱싱(Boolean indexing)"이라고 부르는데, 이름만 거창하고 원리는 단순합니다 — "각 행이 조건을 만족하면 True, 아니면 False"를 만든 다음, True인 행만 골라내는 거예요.

11_filter.py 
# ① 불합격 데이터만 골라내기
fail_df = df_clean[df_clean['합격여부'] == -1]
print(f"불합격 건수: {len(fail_df)}건")

# ② 온도가 305도를 넘는 공정
high_temp_df = df_clean[df_clean['온도_섭씨'] > 305]
print(f"고온 공정 수: {len(high_temp_df)}건")

# ③ 여러 조건 동시에 (AND는 &, OR은 |, 괄호 필수!)
condition = (df_clean['온도_섭씨'] > 305) & (df_clean['두께_nm'] > 103)
risk_df = df_clean[condition]
print(f"고온+두꺼움 공정: {len(risk_df)}건")
❗

여러 조건은 반드시 괄호로 묶으세요
(A) & (B) 처럼 각 조건을 괄호로 감싸야 합니다. 안 그러면 우선순위 때문에 에러가 나거나 엉뚱한 결과가 나와요. 그리고 AND는 &, OR은 |를 씁니다 (파이썬 기본 and/or가 아님!). pandas는 시리즈 전체에 한 번에 적용해야 하기 때문에 비트 연산자를 쓰는 거예요.

groupby — 그룹별로 통계 내기

이제 본격적으로 분석에 들어갑니다! 우리의 핵심 질문은 "합격 공정과 불합격 공정은 센서값에서 어떻게 다른가?"입니다. 이걸 한 줄로 답해주는 강력한 함수가 groupby()예요. 오늘 배우는 것 중 가장 많이 써먹게 될 함수입니다.

📊

groupby = 엑셀의 피벗 테이블이라고 생각하세요. "합격 그룹과 불합격 그룹으로 나눠서, 각 그룹의 평균 온도가 얼마인지" 한 번에 계산해 줍니다. groupby의 기본 패턴은 "① 어떤 기준으로 나눌 것인가 → ② 어떤 컬럼을 → ③ 어떻게 집계할 것인가"의 3단 구성이에요.

12_groupby.py 
# 숫자 컬럼 리스트 (3단계에서 정의한 것과 동일)

                '진공도_mTorr', '두께_nm', '습도_pct', '진동_mm_s',

# 합격여부별 모든 컬럼의 평균
group_mean = df_clean.groupby('result')[numeric_cols].mean().round(2)

상관관계 히트맵 — 변수들 간의 관계

12개 변수가 서로 얼마나 관련 있는지 한 번에 보여주는 표입니다. 색이 진할수록 강한 관계, 빨간색은 음의 관계, 초록색은 양의 관계예요. 오늘 분석의 마지막 단계에서, "결국 어떤 센서가 합격여부에 가장 영향을 주는가?"를 한 장의 그림으로 답해줍니다.

📖

상관계수 읽는 법 (−1 ~ +1)
• +1에 가까움 = 한 값이 커지면 다른 값도 같이 큼 (양의 상관)
• −1에 가까움 = 한 값이 커지면 다른 값은 작아짐 (음의 상관)
• 0에 가까움 = 거의 관계 없음
• 대각선은 항상 1.0 (자기 자신과의 상관) → 의미 없음, 무시

특히 "합격여부" 줄에 주목!
오늘 우리가 알고 싶은 건 "어떤 센서값이 합격여부에 영향을 주는가?"입니다. 히트맵에서 합격여부 행(또는 열)을 따라가며 색이 진한 칸을 찾으세요. 그게 합격 예측에 중요한 변수들입니다. 합격여부와 상관계수의 절댓값이 큰 변수일수록, 모델링할 때도 강력한 입력 변수가 될 가능성이 높아요.

⚠️

상관관계 ≠ 인과관계
"같이 움직인다"는 사실이 "한쪽이 원인이다"라는 뜻은 아닙니다. 숨겨진 다른 요인 때문에 같이 변할 수도 있어요. 예를 들어 "아이스크림 판매량과 익사 사고 수"는 상관이 높지만, 아이스크림이 익사의 원인은 아니죠 — 둘 다 "더운 날씨" 때문에 같이 늘어나는 거예요. 상관관계는 의심 가는 변수를 찾는 출발점일 뿐, 결론은 실험으로 확인해야 합니다.

vib_90 = df_clean['진동_mm_s'].quantile(0.9)
high_vib = df_clean[df_clean['진동_mm_s'] >= vib_90]

all_fail = (df_clean['합격여부'] == -1).mean() * 100
vib_fail = (high_vib['합격여부'] == -1).mean() * 100

print(f"진동 상위 10% 기준: {vib_90:.3f} mm/s 이상 ({len(high_vib)}건)")
print(f"전체 불합격 비율: {all_fail:.1f}%")
print(f"진동 상위 10% 불합격 비율: {vib_fail:.1f}%")
print('비율 차이는 원인 확정이 아니라 추가 점검이 필요한 단서입니다.')
