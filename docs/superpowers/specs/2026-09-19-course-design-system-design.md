# 강좌 페이지 공통 디자인 시스템 설계

## 목적

`stitch-reference/code.html`, `DESIGN.md`, `screen.png`에 정의된 FabMetric Telemetry 디자인을 기존 강좌 페이지에 적용한다. 한국어 강의 내용과 현재 상호작용은 유지하면서 화면을 정밀한 기술 문서 및 분석 대시보드 분위기로 통일한다.

이번 변경은 다음 세 강좌를 대상으로 한다.

- `Web/판다스_수업자료.html` (01 판다스 수업자료)
- `Web/반도체_공정_데이터분석.html` (05 반도체 공정 데이터 분석)
- `Web/실전_반도체_공정_데이터분석_강의자료.html` (06 실전 반도체 공정 데이터 분석)

`Web/`의 다른 강좌는 독립적인 마크업과 스타일 구조를 사용하므로 이번 변경에서 일괄 적용하지 않는다. 대신 이후 페이지가 동일한 디자인 시스템을 명시적으로 선택할 수 있는 재사용 구조를 제공한다.

## 현재 상태

세 페이지는 모두 단일 HTML 파일에 자체 CSS와 JavaScript를 포함한다.

- 01은 차시 탭으로 본문을 전환하는 구조다.
- 05와 06은 고정 목차, 단계별 섹션, 스크롤 위치 추적을 공유한다.
- 각 페이지에 코드 복사, 표, 안내 상자, 실습 및 AI 학습 섹션이 있다.
- 기존 팔레트와 헤더 표현이 서로 달라 하나의 강좌 시리즈처럼 보이지 않는다.
- 모바일 레이아웃은 동작하지만 시각적 밀도와 표 및 코드 영역의 일관성이 부족하다.

## 선택한 접근법

공통 디자인 토큰과 컴포넌트 규칙을 별도 CSS 파일로 만들고, 기존 페이지에는 레이아웃 종류를 나타내는 데이터 속성을 추가한다.

새 파일:

- `Web/assets/course-design-system.css`

페이지 연결 방식:

```html
<link rel="stylesheet" href="./assets/course-design-system.css">
<body data-course-theme="fabmetric" data-course-layout="tabs">
```

05와 06은 `data-course-layout="toc"`를 사용한다. 공통 규칙은 `data-course-theme="fabmetric"` 아래로 한정해 다른 강좌에 영향을 주지 않는다.

Tailwind CDN이나 신규 JavaScript 프레임워크는 도입하지 않는다. 참조 HTML의 디자인 토큰과 시각 언어만 순수 CSS로 옮겨 현재 정적 사이트 구조와 배포 방식을 유지한다.

## 디자인 토큰

공통 CSS의 최상위 테마 범위에 다음 역할 기반 변수를 정의한다.

- 캔버스: `#F8FAFC`
- 카드: `#FFFFFF`
- 낮은 강조 면: `#F1F5F9`
- 기본 텍스트: `#0F172A`
- 보조 텍스트: `#64748B`
- 경계선: `#E2E8F0`
- 주요 동작 및 활성 상태: `#2563EB`
- 센서 및 보조 신호: `#06B6D4`
- 머신러닝 및 고급 단계: `#7C3AED`
- 성공: `#10B981`
- 경고: `#F59E0B`
- 오류 및 불량: `#EF4444`

본문 글꼴은 `Inter`, `Pretendard`, `Noto Sans KR`, 시스템 글꼴 순서로 사용한다. 코드와 수치 데이터는 `JetBrains Mono`를 사용한다. 외부 글꼴 로딩 실패 시에도 레이아웃이 유지되도록 시스템 대체 글꼴을 반드시 포함한다.

기본 간격은 4px 단위를 사용한다. 카드 반경은 8px 이하를 기본으로 하고, 버튼과 입력 요소도 8px을 넘지 않는다. 그림자보다 1px 경계선과 표면색 차이로 계층을 표현한다.

## 공통 컴포넌트

### 헤더

기존의 장식용 그라데이션과 원형 배경 효과를 제거한다. 밝은 표면 위에 얇은 기술 격자와 파란 강조선을 사용하며, 제목·설명·기술 태그가 한눈에 읽히는 조밀한 구성을 만든다. 제목은 모바일 28px, 데스크톱 36px을 기준으로 하고 뷰포트 폭에 따라 글자 크기를 연속 확대하지 않는다.

### 탐색

01의 차시 탭은 기존 클릭 동작을 유지하면서 활성 탭을 파란 배경과 하단 강조선으로 표시한다. 05와 06의 목차는 데스크톱에서 240px 고정 열로 유지하고, 모바일에서는 본문 위의 가로 또는 간결한 목록으로 배치한다. 기존 앵커와 스크롤 추적 JavaScript는 변경하지 않는다.

### 섹션과 카드

큰 단계 섹션은 캔버스 위의 흰색 모듈로 표현한다. 단계별 의미는 파랑, 청록, 보라, 경고색의 왼쪽 3px 신호선과 작은 번호 배지로 구분한다. 카드 안에 또 다른 장식용 카드를 중첩하지 않고, 내부 하위 내용은 구분선과 낮은 강조 면으로 정리한다.

### 코드 블록

코드 영역은 짙은 네이비 배경, 고정폭 글꼴, 충분한 대비를 사용한다. 파일명 및 언어 헤더는 별도 도구막대로 보이게 하고 복사 버튼에는 명확한 hover, focus, copied 상태를 제공한다. 모바일에서는 가로 스크롤을 허용하고 코드 줄을 강제로 줄바꿈하지 않는다.

### 표와 데이터 패널

표 헤더는 낮은 강조 면과 12px 굵은 글꼴을 사용한다. 행은 1px 구분선과 hover 상태를 가진다. 수치에는 고정폭 글꼴과 tabular 숫자 기능을 적용한다. 작은 화면에서는 표 컨테이너만 가로 스크롤되고 페이지 전체는 넘치지 않아야 한다.

### 상태 및 학습 안내

학습 목표, 팁, 주의, 오류, 결과, AI 학습 섹션은 같은 카드 골격을 공유하되 의미에 따라 파랑·청록·보라·주황·빨강을 사용한다. 색상만으로 의미를 전달하지 않고 기존 제목과 아이콘을 유지한다.

## 페이지별 어댑터

### 01 판다스 수업자료

`site-header`, `nav-bar`, `session-header`, `objectives`, `content-card`, `code-block`, `data-table` 등 기존 클래스를 공통 토큰에 매핑한다. 탭 표시와 `session-pane` 전환 방식은 그대로 둔다. 판다스 페이지의 교육적이고 친근한 내용은 유지하되 색과 표면 체계를 기술 문서형 디자인으로 통일한다.

### 05 및 06 반도체 강좌

두 페이지가 공유하는 `header`, `layout`, `toc`, `section`, `subsection`, `code-wrap`, `tbl-wrap`, `callout` 계열 클래스를 같은 규칙으로 처리한다. 06의 중급 및 머신러닝 단계는 보라색, 불량 및 위험 상태는 빨간색을 제한적으로 사용해 05와 구분한다.

## 반응형 동작

- 1280px 이상: 240px 목차와 최대 960~1040px 본문을 나란히 표시한다.
- 768px 이상 1279px 이하: 본문 폭을 우선하고 여백과 카드 내부 간격을 줄인다.
- 767px 이하: 단일 열로 전환하고 목차는 본문 위에 배치한다.
- 모바일 카드 패딩은 16px, 페이지 좌우 여백은 16px을 기준으로 한다.
- 버튼과 탭의 최소 터치 높이는 40px을 유지한다.
- 긴 한국어 제목과 코드 식별자는 부모 밖으로 넘치지 않게 한다.
- 표와 코드만 자체 가로 스크롤을 허용한다.

## 접근성 및 상호작용

- 모든 링크와 버튼에 `:focus-visible` 표시를 제공한다.
- 본문과 보조 텍스트는 WCAG AA 수준의 대비를 목표로 한다.
- `prefers-reduced-motion: reduce`에서는 전환과 스크롤 애니메이션을 최소화한다.
- 프린트 시 목차와 복사 버튼을 숨기고 본문과 코드가 검정 텍스트 중심으로 출력되게 한다.
- 기존 탭, 목차 앵커, 코드 복사, IntersectionObserver 동작을 보존한다.

## 변경 범위

수정 대상:

- 공통 CSS 신규 생성
- 세 HTML 파일에 CSS 링크와 테마 및 레이아웃 속성 추가
- 새 스타일이 기존 인라인 CSS보다 뒤에 적용되도록 `<head>` 연결 순서 조정
- 필요 시 스타일 충돌을 해소하기 위한 최소한의 클래스 또는 속성 추가
- `npm run build`로 `Web/index.html` 재생성

변경하지 않는 항목:

- 한국어 강의 내용, 예제 코드, 데이터 파일
- 탭 또는 목차의 정보 구조
- 복사 버튼 및 스크롤 추적의 JavaScript 로직
- `stitch-reference` 원본 파일
- 이번 범위 밖의 강좌 페이지 디자인

## 오류 격리

공통 CSS는 테마 데이터 속성 아래로 한정한다. CSS 파일을 불러오지 못하더라도 기존 인라인 CSS가 남아 있어 페이지 내용과 기능은 계속 사용할 수 있다. 한 페이지의 어댑터 규칙은 레이아웃 데이터 속성으로 분리해 다른 구조에 잘못 적용되지 않게 한다.

## 검증

1. `npm run build`가 성공하고 `Web/index.html`이 `Web/order.txt`와 일치하는지 확인한다.
2. 세 HTML 파일의 UTF-8 한국어가 손상되지 않았는지 확인한다.
3. 1440x900 데스크톱과 390x844 모바일에서 세 페이지를 렌더링한다.
4. 페이지 전체 가로 오버플로, 텍스트 겹침, 잘린 버튼 및 카드 높이 변화를 확인한다.
5. 01의 세 차시 탭을 전환하고 활성 상태를 확인한다.
6. 05와 06의 목차 링크 및 스크롤 활성 상태를 확인한다.
7. 각 페이지에서 코드 복사 버튼이 동작하고 copied 상태가 보이는지 확인한다.
8. 표와 코드 블록이 모바일에서 페이지 전체가 아닌 자체 영역에서 스크롤되는지 확인한다.
9. 브라우저 콘솔 오류와 누락된 로컬 자산 요청을 확인한다.
10. 프린트 미리보기에서 불필요한 탐색 요소가 숨겨지는지 확인한다.

## 완료 기준

세 강좌가 동일한 FabMetric 디자인 체계로 보이고, 기존 강의 내용과 상호작용이 유지되며, 데스크톱과 모바일에서 읽기 쉽고 가로 오버플로가 없어야 한다. 새 강좌는 공통 CSS 링크와 두 데이터 속성 중 적절한 레이아웃 값을 지정하여 같은 스타일을 적용할 수 있어야 한다.
